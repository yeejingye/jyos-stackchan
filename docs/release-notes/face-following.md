# Follow my Face

Release impact: minor.

The M5StackChan CoreS3 host firmware adds **Follow my Face** to the hamburger menu. It raises the head about 45 degrees, runs local face detection, and continuously adjusts yaw and pitch to keep the largest detected face centered. The menu is installed by the host even when a MOD replaces the default startup behavior. No camera frames are uploaded. A **Stop** square-icon button appears over the face only during the session; stopping releases camera inference and servo torque, leaving the last head position rather than commanding a return movement.

Tracking yields after synchronous inference before sending servo commands, and retries transient SCServo acknowledgement timeouts up to three total attempts with cancellation-aware backoff. Persistent errors stop the session and release its resources. Diagnostic logs include detection counts, normalized face coordinates, inference timing, and motor acknowledgements. Tracking uses a center dead zone and small movement steps, and holds position while no face is detected. Camera orientations are searched automatically. Requested motion is bounded to ±60 degrees yaw and 0–60 degrees upward pitch; the servo driver's own limits also apply. Camera preview, servo tests, and random looking stop tracking before taking over. Starting during camera capture or a petting/servo motion is refused until that action finishes.

Future voice handlers can import `startFaceFollowing(robot)` and `stopFaceFollowing(robot)` from the host module `face-following`; `isFaceFollowing(robot)` exposes the session state. They operate the same controller and Stop overlay as the menu. `startFaceFollowing` is idempotent and starts asynchronously; `stopFaceFollowing` returns a promise that resolves after in-flight work and resource cleanup. Runtime shutdown also stops the session. Other hardware hosts omit this menu item unless they provide the local detector and a camera.

Tracking acquires very confident detections immediately and confirms weaker detections across frames. Corrections blend over the measured capture interval with light coordinate filtering. There is no fixed tracking delay beyond a brief event-loop yield. The confirmed camera orientation stays locked for the session, including prolonged face loss, and is reused when restarting the mode.

Validation: controller tests cover tracking, capture cadence, loss of detection, bounds, duplicate starts, cancellation during startup/capture, restart, and resource failures. Orientation tests check pixel rotation, coordinate mapping, and recovery after face loss. The XS face-init test checks menu start, Stop icon action, and external start/stop UI lifecycle. Physical CoreS3 logs confirm face detection, motor acknowledgements, and recovery from transient servo timeouts; perceived smoothness and detection distance still require live verification. Build and flash the default host with `npm run build` / `npm run deploy` from `firmware/`.

An optional diagnostic manifest and `firmware/tools/face-following/sweep.py` compare four bounded tracking profiles in eight live stages. The script records per-frame detections and command timing, produces a scored report, and generates a normal-mode settings manifest only when visibility and sample coverage support a comparison. Stop cancels the sweep; automatic completion uses the same resource cleanup. The report measures image-space error and commanded movement, with physical smoothness requiring observation. See `firmware/tools/face-following/README.md` for reproduction and scoring limits.

Live tuning selected the Smooth preset from the user's physical observation after eight stages: motor corrections at least 300 ms apart, coordinate weight 0.4, gain 0.3, dead zone 6%, maximum step 2.86 degrees, and a movement interval multiplier of 1.5 (bounded to 180–600 ms). Detection continues between corrections. The automatic score remained inconclusive because visibility differed between settings; the selection accepts greater measured following lag for the preferred physical movement quality. The diagnostic baseline remains unchanged for future comparisons.
